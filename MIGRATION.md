## 1. Project Overview

A Node.js/TypeScript monorepo that generates, manages, and deploys local SEO landing pages.
Pages are created by cross-joining services × locations, scored for AI-readiness, and deployed
to a live server via FTP.

**Target domains (production)**
- App: `app.localseongine.com` or `app.inboxingproweb.com`
- Generated pages: `local.inboxingproweb.com` or `preview.localseongine.com`

**Stack**
| Concern | Technology |
|---|---|
| Runtime | Node.js 24 |
| Language | TypeScript 5.9 |
| Framework | Express 5 |
| ORM | Drizzle ORM |
| Database | PostgreSQL |
| Build tool | esbuild |
| Package manager | pnpm (workspaces) |
| AI content | OpenAI API |
| AI images | Ideogram API |
| Deployment | FTP (basic-ftp) |
| SEO monitoring | Google Search Console API |

## 3. Environment Variables

Copy `.env.example` to `.env` and fill in all values.

| Variable | Purpose | Where to get it |
|---|---|---|
| `PORT` | Server port (default 8080) | Set to `8080` or preferred port |
| `NODE_ENV` | `production` on live server | Set manually |
| `LOG_LEVEL` | Pino log level (`info`, `debug`, `warn`) | Set to `info` for production |
| `SESSION_SECRET` | Signs Express session cookies | Generate: `openssl rand -base64 32` |
| `OPENAI_API_KEY` | Content generation, scoring, social posts | https://platform.openai.com/api-keys |
| `IDEOGRAM_API_KEY` | AI image generation (hero, support, trust, conversion) | https://ideogram.ai/manage-api |
| `DEPLOY_USERNAME` | FTP username for page deployment | Your web hosting FTP credentials |
| `DEPLOY_PASSWORD` | FTP password for page deployment | Your web hosting FTP credentials |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | GSC URL inspection API (indexing checks) | Google Cloud Console → IAM → Service Accounts |
| `GSC_OAUTH_CLIENT_ID` | GSC keyword/position tracking | Google Cloud Console → Credentials |
| `GSC_OAUTH_CLIENT_SECRET` | GSC keyword/position tracking | Google Cloud Console → Credentials |
| `GSC_OAUTH_REFRESH_TOKEN` | GSC keyword/position tracking | OAuth flow on first auth |
| `DATABASE_URL` | PostgreSQL connection string | Your DB provider |
| `MAX_MONTHLY_SERVER_IMAGES` | Cap on AI image generation per month | Set to `200` or your budget limit |

**Replit-specific variables NOT needed on VPS:**
- `REPLIT_DEV_DOMAIN`
- `REPLIT_DOMAINS`
- `AI_INTEGRATIONS_OPENAI_API_KEY`
- `AI_INTEGRATIONS_OPENAI_BASE_URL`

> **Note on OpenAI**: On Replit the app uses `AI_INTEGRATIONS_OPENAI_*` (a Replit-managed proxy).
> On VPS, set `OPENAI_API_KEY` directly instead.

## 4. Data Storage

### Important: Dual storage model

The app uses **two storage layers**:

1. **JSON files in `config/`** — the primary data store for all project, campaign, and user data
2. **PostgreSQL via Drizzle ORM** — used for session storage and user accounts (the DB schema has minimal tables; most business data lives in JSON files)

### JSON config files (primary — must be migrated)

| File/Directory | Contents |
|---|---|
| `config/projects/{slug}.json` | Full project config: business details, FTP settings, deploy config, nav items, services |
| `config/projects/{slug}/brand-profile.json` | Brand colours, fonts, tone imported from existing site |
| `config/projects/{slug}/providers/{serviceKey}.json` | Customer provider profiles for non-digital campaigns |
| `config/campaigns/` | Campaign records (services, areas, status, stage) |
| `config/areas/` | Location/area definitions and cluster configs |
| `config/users.json` | User accounts with bcrypt-hashed passwords |
| `config/sitemap-registry.json` | Sitemaps registered for Google Search Console |
| `config/industryProfiles.json` | Industry-specific content guidance |
| `config/imagePacks.json` | Image pack definitions |

### Generated output (must be migrated if preserving existing pages)

| Directory | Contents |
|---|---|
| `output/{slug}/` | All generated HTML pages |
| `output/{slug}/assets/` | Project-specific images (namespaced) |
| `output/{slug}/uploads/` | Uploaded business images |
| `output/{slug}/session.json` | Wizard session state |
| `output/{slug}/live-crawl.json` | Cached crawl report |

### Database (PostgreSQL)

The DB is used for session storage and user accounts. The schema uses Drizzle ORM.

**To migrate the DB schema to a new server:**
```bash
# After setting DATABASE_URL in .env:
pnpm db:push
```

**To back up current data:**
```bash
pg_dump $DATABASE_URL > backup_$(date +%Y%m%d).sql
```

**To restore on new server:**
```bash
psql $DATABASE_URL < backup_YYYYMMDD.sql
```

> **Note**: Because most data is in JSON files, the most critical backup is the `config/` directory
> and the `output/` directory, not the database. Back these up first.

## 5. File Storage & Image Library

### Where images live

| Location | Contents | Example path |
|---|---|---|
| `output/{slug}/assets/{service}/` | Library images for a service type | `output/inboxingproweb/assets/web-design/hero-1.webp` |
| `output/{slug}/uploads/` | Uploaded images (original + processed) | `output/inboxingproweb/uploads/1778161218166.webp` |
| `output/{slug}/assets/` | Generated and AI images for this project | `output/inboxingproweb/assets/` |

### Image roles

Each page uses 4 role images:

| Role | Purpose |
|---|---|
| `hero` | Above-the-fold banner image |
| `support` | Content section supporting image |
| `trust` | Trust/social proof image |
| `conversion` | CTA/bottom conversion image |

### Image URL resolution

- **Local development**: images served via `/api/images/serve/{clientSlug}/{role}`
- **Live (deployed)**: images are patched to absolute URLs pointing to `{domain}/assets/{clientSlug}/{filename}` at deploy time by `patchImageSrcs()` in `searchConsole.ts`

### Migrating images to a new server

1. Copy entire `output/{slug}/assets/` directory to the new server
2. Copy entire `output/{slug}/uploads/` directory to the new server
3. The FTP deploy (`POST /api/pages/deploy`) handles uploading assets and pages in one step — it will upload `assets/` to `/assets/{clientSlug}/` on the live site

## 6. Build & Run Commands

### Requirements

- **Node.js**: 24.x (confirmed: v24.13.0)
- **Package manager**: pnpm (do NOT use npm or yarn)
- **Install pnpm**: `npm install -g pnpm`

### Install dependencies

```bash
pnpm install
```

### Development (with watch/rebuild)

```bash
pnpm --filter @workspace/api-server run dev
```

This runs: `NODE_ENV=development && build && start`

The server listens on `PORT` (default 8080).

### Production build

```bash
pnpm --filter @workspace/api-server run build
```

Compiles TypeScript to `artifacts/api-server/dist/index.mjs` using esbuild.
Always rebuild after any source code change.

### Production start

```bash
pnpm --filter @workspace/api-server run start
```

Or directly: `node --enable-source-maps artifacts/api-server/dist/index.mjs`

### Database migration

```bash
pnpm db:push
```

Applies the Drizzle schema to the PostgreSQL database (run once on setup).

### Type checking

```bash
pnpm run typecheck
```

### Additional commands

| Command | Purpose |
|---|---|
| `pnpm --filter @workspace/api-server run build` | Compile TypeScript to dist/ |
| `pnpm --filter @workspace/api-server run start` | Start compiled server |
| `pnpm run typecheck` | Full type-check across workspace |
| `pnpm db:push` | Push Drizzle schema to DB |

## 7. VPS Deployment

### Recommended server spec

- Ubuntu 22.04 LTS or similar
- 2+ vCPU, 2 GB RAM minimum (4 GB recommended for page generation jobs)
- Node.js 24.x
- PostgreSQL 15+
- PM2 for process management
- Nginx as reverse proxy

### Step-by-step setup

```bash
# 1. Install Node 24 via nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
nvm install 24
nvm use 24

# 2. Install pnpm
npm install -g pnpm

# 3. Clone / upload the project
# (transfer the full repo including config/ and output/ directories)

# 4. Install dependencies
pnpm install --frozen-lockfile

# 5. Create .env from template
cp .env.example .env
nano .env   # Fill in all values

# 6. Apply DB schema
pnpm db:push

# 7. Build the app
pnpm --filter @workspace/api-server run build

# 8. Start with PM2
pm2 start "node --enable-source-maps artifacts/api-server/dist/index.mjs" \
  --name "localseo-api" \
  --env production

pm2 save
pm2 startup   # Enable restart on reboot
```

### PM2 ecosystem file (recommended)

Create `ecosystem.config.cjs` in the project root:

```javascript
module.exports = {
  apps: [{
    name: 'localseo-api',
    script: 'artifacts/api-server/dist/index.mjs',
    node_args: '--enable-source-maps',
    env: {
      NODE_ENV: 'production',
      PORT: 8080,
    },
    instances: 1,
    autorestart: true,
    max_memory_restart: '1G',
  }],
};
```

Then: `pm2 start ecosystem.config.cjs`

### Nginx reverse proxy

```nginx
server {
    listen 80;
    server_name app.localseongine.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name app.localseongine.com;

    ssl_certificate     /etc/letsencrypt/live/app.localseongine.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.localseongine.com/privkey.pem;

    # Increase timeout for FTP deploys and rollout jobs (can take 3+ minutes)
    proxy_read_timeout 600;
    proxy_connect_timeout 60;
    proxy_send_timeout 600;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

Install SSL: `certbot --nginx -d app.localseongine.com`

### File permissions

```bash
# Output and config directories must be writable by the Node process
chmod -R 755 output/
chmod -R 755 config/
```

### Cron jobs

No required cron jobs. The following are optional for scheduled checks:
- Keyword rank tracking: trigger manually via dashboard or set up a cron to call `POST /api/keyword-tracking/{slug}/run`
- Index status: trigger manually via dashboard

## 8. CORS Configuration for VPS

The app currently restricts CORS to Replit origins in `artifacts/api-server/src/app.ts`.
**Before deploying to VPS, update the allowed origins** to include your production domain.

Find this block in `src/app.ts`:

```typescript
const ALLOWED_ORIGINS: string[] = [
  "http://localhost",
  "http://localhost:8080",
  // ...Replit-specific entries...
];
```

Add your VPS domains:

```typescript
const ALLOWED_ORIGINS: string[] = [
  "http://localhost",
  "http://localhost:8080",
  "https://app.localseongine.com",
  "https://app.inboxingproweb.com",
  ...(process.env.APP_DOMAIN ? [process.env.APP_DOMAIN] : []),
];
```

Then rebuild: `pnpm --filter @workspace/api-server run build`
